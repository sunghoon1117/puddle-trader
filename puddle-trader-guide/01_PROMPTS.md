# 웅덩이 트레이더 — 단계별 프롬프트 모음 (Claude Code용)

> 목적: 팀원이 **같은 순서·같은 품질**로 앱을 처음부터 다시 만들 수 있도록, 실제 진행에 쓴 요청을 일반화해 정리했습니다.
> 사용법: 위에서부터 한 단계씩 Claude Code에 붙여넣고, 각 단계의 **완료 기준**을 확인한 뒤 다음 단계로 넘어갑니다.
> `<...>` 로 표시된 부분은 팀 상황에 맞게 바꾸세요. 개인정보(이메일·계정명·키)는 프롬프트에 직접 쓰지 말고, 필요한 값은 4단계의 "비밀 값" 절차로만 다루세요.

## 0. 공통 규칙 (모든 단계 맨 앞에 붙이는 시스템 지침)

```
너는 주식 매매 기준·추천 앱을 만드는 개발자다. 다음 규칙을 항상 지킨다.
1) 사용자 환경은 모바일 우선이며 PC/Claude 없이 휴대폰만으로 운영 가능해야 한다.
2) 정확성이 최우선이다. 모든 규칙은 과거 데이터로 검증하고, 결과가 나쁘면 나쁘다고 그대로 보고한다(과장·생존편향 숨김 금지).
3) 검증은 "아무 날이나 샀을 때(기준선)"와 반드시 비교하고, 학습/검증 구간을 분리(워크포워드)한다.
4) 미래 데이터 참조 금지(룩어헤드 금지): 모든 지표는 해당 시점까지의 데이터만 사용한다.
5) 접근 제한(403/429/봇 차단/CAPTCHA)을 만나면 헤더 위장·IP 우회 등으로 뚫지 말고, 이전 데이터를 유지한 채 상태를 표시하고 재시도한다.
6) 개인정보·비밀(이메일, API 키, 토큰, 로컬 경로, 계정명)을 코드·문서·공개 저장소·채팅에 노출하지 않는다. 비밀은 호스팅 서비스의 Secrets에만 둔다.
7) 계정 가입·로그인·결제는 대신하지 않는다. 사용자가 직접 해야 할 단계는 정확한 클릭 순서로 안내하고 기다린다.
8) 유료 서비스·유료 API는 쓰지 않는다(무료 한도 내). 불필요한 기능은 빼고, 뺀 것은 이유와 대체 수단을 보고한다.
9) 투자 권유·수익 보장 표현 금지. 면책 문구를 화면에 둔다.
```

## 1단계. 조사 — 두 채널(관점) 영상 파악

```
유튜브 채널 <채널A 주소>, <채널B 주소>의 모든 영상을 확인해서 매매 관점과 기준을 정리해줘.
영상을 직접 볼 수 없으면 자동 자막(한국어)을 받아서 읽어. 
- 먼저 전체 영상 목록(영상/라이브/쇼츠 탭 모두)을 만들고,
- 자막은 yt-dlp로 내려받되 이어받기가 되게(이미 받은 건 건너뛰기), 유튜브가 요청을 제한하면 5분 대기 후 자동 재개하게 만들어줘(우회 금지).
- 자막은 정리된 텍스트(.txt)와 메타(제목·날짜)로 저장하고, 개인정보 동기화 폴더(OneDrive 등) 밖에 저장해줘.
- 읽은 뒤에는 각 채널의 매매 원칙을 '원칙 / 근거 영상 ID' 형태로 요약해줘.
```
**완료 기준**: 전체 영상 목록 수, 자막 확보 수, 채널별 핵심 원칙 요약(근거 영상 ID 포함).
**주의**: Windows에서 파일 저장 시 한글/이모지 제목 때문에 cp949 인코딩 오류가 난다 → 모든 `open()`에 `encoding="utf8"` 명시.

## 2단계. 규칙화 — 관점을 점수 엔진으로

```
두 채널의 관점을 '검증 가능한 규칙(숫자)'으로 바꿔서 엔진을 만들어줘.
- 관점1(웅덩이): 낙폭, 200일선 이격, 주봉 RSI, 일봉 RSI, MACD 골든크로스, 200주선 근접, 추세 돌파, VIX, 공포지수, 시장 폭, VIX 기간구조 역전, 계절성 → 가중 합산 점수(0~100), 1·2·3차 분할매수 임계값, 현금 비중·차수별 사용 비율.
- 관점2(도키): 영업현금흐름 기반 적정가(성장률 5~20% 보수적, 멀티플 18배, 요구수익률 10%), 저점 위치, 과매수 회피, 200일선 지지, 고평가 감점.
- 관점3(통합): 두 점수의 평균 + 두 관점이 동의하면 가점, 한쪽이 매우 낮으면 감점.
- 과열(주봉 RSI 70↑ 등)이면 점수와 무관하게 신규 매수 중단. 3배 레버리지는 2차까지, 구조적 약세·고평가는 1차로 제한.
- 레버리지 종목은 낙폭/이격을 배율로 나눠 기초지수 기준으로 환산.
- 핵심: 라이브 추천과 백테스트가 '같은 코드(engine.js)'를 쓰게 하고, 브라우저와 Web Worker 양쪽에서 돌게 해줘.
- 수동 입력 신호(공포탐욕, 시장 폭, 헤지펀드 포지션, 계절성)는 가격 데이터로 자동 계산하는 대체 지표로 만들어줘.
```
**완료 기준**: `engine.js` 하나로 점수·차수·과열·설명(체크리스트)이 나오고, 과거 어느 날짜든 같은 함수로 계산된다.

## 3단계. 검증 — 과거 매매 시뮬레이션과 자동 보정

```
이 규칙대로 과거에 매매했다면 수익(승률)이 어땠는지 검증하고, 결과로 스스로 기준을 조정하게 해줘.
1) 이벤트 연구: 신호가 처음 켜진 날(웅덩이당 차수별 1회)의 이후 20/60/120/250일 상승 확률·평균수익·60일 내 최대낙폭(MAE). 같은 종목 구성에서 '아무 날 매수' 기준선과 비교.
2) 표본 외 검증: 전체 기간의 앞 70%로 학습, 뒤 30%로 검증. 
3) 강건성 점검: 보정 없이 기본 파라미터를 지수·섹터 ETF 약 13개(1990년대~)에 적용(생존편향 완화).
4) 매매 시뮬레이션: 초기 50% 보유 + 신호 단계별 추가 매수, 다음 거래일 종가 체결, 단순 보유/50% 방치와 비교(연수익률·최대낙폭·칼마).
5) 자동 보정(워크포워드): 신호별 효과(z)로 가중치 0.4~1.6배 조정, 임계값 격자 탐색, 학습에 안 쓴 구간에서 기본값보다 나을 때만 채택, 채택 시 기본값 쪽으로 50% 되돌려 안정화.
6) 후보 선택도 자동화: 공포지수 v1/v2 비교, 익절·감량 규칙 유무 비교 → 효과 큰 쪽 자동 선택.
7) 검증은 Web Worker에서 돌려 UI가 멈추지 않게 하고, 엔진 버전이 바뀌면 저장된 결과를 자동 재생성.
8) 결과가 기대와 다르면(예: 단순 보유를 못 이김, 익절이 오히려 손해) 그대로 보고하고 앱 동작에 반영해줘.
```
**완료 기준**: 검증 화면에 ①기준선 대비 승률 ②단계별(1·2·3차) 승률 ③표본 외 ④중립 ETF ⑤시뮬레이션 ⑥보정 현황이 나온다.
**기대 가능한 결과(참고)**: 60일 상승 확률 +5%p 안팎(신호가 겹칠수록↑), 120일 이상은 차이 거의 없음, 단순 보유와 수익률 동급, 익절 규칙은 손해 → "신규 매수만 중단"으로 안내.

## 4단계. 데이터 파이프라인 — 지연·끊김 대응

```
시세 데이터를 지연·끊김 없이 받도록 파이프라인을 만들어줘(무료만 사용).
- tools/update_data.py: 야후 차트(비공식)에서 일봉 전체 이력을 받아 data/px/<심볼>.json 으로 저장. 기존 파일이 있으면 최근 1개월만 받아 병합(실패해도 기존 값 유지), data/manifest.json 에 갱신 시각·실패 목록 기록. 호스트 2개(query1/2)로 재시도.
- 재무(개별주): 연간 영업현금흐름·희석주식수로 주당 현금흐름과 보수적 성장률로 적정가 자동 계산 → data/fund.json.
- 앱은 우선순위: ① 같은 출처 data/ (manifest 변화만 보고 바뀐 종목만 내려받기) → ② 프록시/직접 → ③ IndexedDB의 마지막 정상 저장본. 어느 경로가 막혀도 화면은 비지 않게.
- 신선도 칩(정상/지연/오래됨)과 '장중 잠정' 표시.
- 자동 갱신: 앱을 켜 둔 동안 장중 2분·장외 10분, 화면 복귀·온라인 복귀 시 즉시, 당겨서 새로고침.
- (선택) 실시간 계층: 여러 종목 최근 일봉을 한 번에 주는 /api/batch 를 가진 Cloudflare Worker(무료)와, 앱의 10초 폴링.
- 로컬 개발용 server.py: 정적 파일 + 백그라운드 갱신 + /api/chart, /api/batch.
```
**완료 기준**: 인터넷이 끊겨도 마지막 데이터로 화면이 열리고, 상단 칩이 상태를 정확히 표시한다.

## 5단계. 모바일 우선 UI

```
모바일(375px)을 기준으로 설계해줘. 데스크탑은 같은 코드의 확장.
- 하단 탭: 오늘 / 종목 / 거물 / 검증 / 내 계좌, 설정은 헤더의 ⚙.
- 상단 고정: 관점 전환(웅덩이/도키/통합), 데이터 신선도 칩, 새로고침.
- 오늘: 시장 온도·VIX·공포지수·시장 폭, '오늘의 행동' 카드(점수 링, 차수, 권장 금액·주수, 3관점 점수), 신호 변화, 최근 거물 매수, 두 채널 새 영상/최근 30일 종목 언급, 3관점 표.
- 종목: 가로 스크롤 칩, 가격·200일선·과거 신호 마커 차트(터치로 값 표시), 신호 체크리스트(근거 수치 포함), 이 종목의 과거 성과, 자동 적정가, 거물·내부자 거래.
- 내 계좌: 현금·보유 입력, 가용 현금(최소 유지 현금 제외), 단일 종목/레버리지 한도, 스트레스 테스트, 매매 기록(같은 차수 반복 추천 방지).
- 접근성: 터치 타겟 44px, 다크모드, safe-area, 가로 스크롤 방지, 입력 중에는 화면 전체 재렌더 금지(입력 손실 방지).
- PWA: manifest, 아이콘(SVG+PNG 192/512), 서비스 워커(앱 셸 network-first, 시세는 앱이 IndexedDB로 관리).
```
**완료 기준**: 휴대폰 크기에서 가로 스크롤이 없고, 오프라인에서도 열린다.
**흔한 버그**: CSS grid 자식에 `min-width:0` 누락 → 가로 넘침. 장중 시세가 바뀌어도 캐시 키에 마지막 종가를 안 넣으면 신호가 갱신되지 않는다.

## 6단계. 거물 거래(내부자·기관·의원) 통합

```
다른 프로젝트(stock-tracker)의 기능을 이 앱에 통합해줘. 서버/DB 없이 정적 JSON으로.
- tools/tracker_collect.py: SEC Form 4(내부자), 13F-HR(분기 보유와 직전 분기 대비 NEW/ADD/REDUCE/SOLD), 하원 사무처 PTR 색인(제출 사실+원문 PDF 링크), (선택) FMP 의원 거래. 13F의 CUSIP→티커는 OpenFIGI 공개 매핑 사용. 회사별 최근 10-K/10-Q/8-K 공시(8-K 항목 한국어 해석).
- 비밀(SEC 연락처 User-Agent, FMP 키)은 환경변수로만 받는다(Secrets). 이전 상태는 배포된 사이트의 JSON에서 이어받아 증분 수집.
- SEC가 403/429면 즉시 중단(우회 금지), 이전 데이터 유지, status.json 에 상태 기록.
- 앱 '거물' 탭: 피드(필터), 인물, 13F 펀드, 의원. 거래 상세 시트: 규칙 기반 신호 점수(-100~+100)와 근거 목록, SEC 원문 링크. 종목 상세에도 같은 종목의 거래·공시 표시.
- 거래 신호는 이력이 짧아 검증 불가이므로 '참고 정보'로만 표시하고 매수 점수에는 넣지 않는다(화면에 명시).
- AI 심층 분석(유료 API)은 제외하고 규칙 기반 근거 목록으로 대체한다.
```
**완료 기준**: 네트워크가 막혀도 마지막 수집분이 보이고, 상단에 SEC 상태가 표시된다.

## 7단계. 영상 지식 자동 반영

```
두 채널의 새 영상이 계속 올라오므로 자동으로 분석해 반영해줘.
- tools/build_knowledge.py: 수집된 자막에서 채널별 강조 신호(1,000자당 언급), 종목별 언급·우호/경계 표현, 최근 120일 영상별 분석, 전체 영상 목록 → data/knowledge.json.
- tools/youtube_update.py: 공식 RSS 피드로 새 영상 발견 → 자막 분석 시도 → 막히면 우회 없이 '제목 분석'으로 먼저 반영 후 다음 실행에서 보강. 배포본과 저장소 파일 중 더 최신을 기준으로 병합. 
- 휴대폰에서 영상 주소를 붙여넣어 즉시 분석하는 수동 실행 입력칸(workflow_dispatch input).
- 앱: '두 채널 새 영상' 카드와 '최근 30일 종목 언급'. 영상 분석은 점수에 반영하지 않는다(검증 불가).
```

## 8단계. 배포 — 무료·PC 없이

```
GitHub Pages + GitHub Actions 로 배포해줘(공개 저장소, 무료).
- 워크플로: 시세는 5분마다(미국 장중), 거물 거래·영상 분석은 30분마다, 하루 1회 전체 재수집, 수동 실행, push 시 배포. concurrency 로 배포 겹침 방지.
```
