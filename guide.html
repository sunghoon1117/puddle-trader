← 앱으로 돌아가기
무엇을 하나처음 설치매일 쓰는 법점수·차수검증 탭거물 거래새로고침·지연개인정보문제 해결

1. 이 앱이 하는 일

두 유튜브 채널의 매매 관점을 규칙(숫자)으로 바꿔서, 지금 사야 할 때인지·얼마나 살지를 알려 주고, 같은 규칙으로 과거에 샀다면 어땠는지 검증해 스스로 기준을 조정하는 앱입니다.

관점핵심
웅덩이 (developmong)시장이 크게 빠졌을 때(웅덩이)만, 신호가 겹칠 때 1·2·3차로 나눠 매수. 현금 비중을 지킴.
도키 (doki_investing)좋은 기업을 적정가보다 싸게, 과매수 구간은 피하고 꾸준히 모음. 영업현금흐름 기반 적정가.
통합두 관점이 함께 동의할 때 가점, 한쪽이 크게 반대하면 감점. 기본 화면의 관점입니다.

추가로 거물 거래 탭에서 세계 부호·CEO·유명 펀드·의원의 공식 공시(SEC, 하원)를 모아 보여줍니다.

2. 처음 한 번 설치 (이후엔 휴대폰만)

앱 파일을 인터넷에 올리는 최초 1회는 PC가 훨씬 편합니다(휴대폰 브라우저로도 가능하지만 파일이 많아 번거롭습니다). 올린 뒤에는 PC·Claude 없이 휴대폰만으로 계속 갱신되고 사용됩니다.
  1. GitHub 가입(무료) 후 새 공개(Public) 저장소를 만듭니다. 예: puddle-trader
  2. 폴더의 모든 파일(숨김 폴더 .github 포함)을 저장소에 올립니다. (Add file → Upload files)
  3. 저장소 Settings → Pages → Source: GitHub Actions
  4. (권장) Settings → Secrets and variables → Actions → New repository secret
    • SEC_USER_AGENT : 앱이름 이름 이메일 형식(SEC가 요구하는 연락처). 예) MyApp 홍길동 me@example.com — 비밀로 저장되어 사이트에 노출되지 않습니다.
    • FMP_API_KEY : (선택) 의원 거래 상세용. 없으면 하원 공식 색인만 사용.
  5. Actions 탭 → “자동 갱신 + 배포” → Run workflow. 1~3분 뒤 https://계정.github.io/저장소/ 가 열립니다.
  6. 그 주소를 휴대폰에서 열고 홈 화면에 추가합니다. (iPhone: 공유 → 홈 화면에 추가 · Android: 메뉴 → 앱 설치)

참고

저장소에 60일 이상 활동이 없으면 GitHub가 예약 실행을 멈출 수 있습니다. Actions 탭에서 다시 켜면 됩니다.

3. 매일 쓰는 법

  1. 오늘 탭을 엽니다. 위쪽 버튼으로 관점(웅덩이/도키/통합)을 고릅니다.
  2. 오늘의 행동 카드가 있으면 그 종목이 “신호가 겹친 구간”입니다. 카드를 누르면 근거(신호 목록)·차트·과거 성과가 나옵니다.
  3. 카드에 2차 매수 · $1,200 처럼 나오면: 내 내 계좌 탭의 현금·보유를 기준으로 계산한 권장 금액입니다. 한 번에 다 사지 않고 차수별로 나눕니다.
  4. 산 뒤에는 이 매수를 기록 버튼(종목 화면)으로 기록하면 같은 차수를 반복 추천하지 않습니다.
  5. “관망/관찰”이면 아무것도 하지 않는 것이 규칙입니다. 아무 때나 사지 않는 것이 이 전략의 핵심입니다.

먼저 내 계좌 탭에서 현금과 보유 종목(수량·평단)을 입력하세요. 입력하지 않으면 금액 대신 “가용 현금의 몇 %”로만 안내합니다. 이 정보는 휴대폰 안에만 저장됩니다.

4. 점수·차수 읽는 법

  • 점수(0~100): 여러 신호(낙폭, 200일선, 주봉 RSI, VIX·공포지수, 시장 폭 등)를 가중 합산. 높을수록 “웅덩이가 깊고 반등 근거가 겹침”.
  • 1·2·3차: 점수가 임계값을 넘는 단계. 높은 차수일수록 과거에 60일 뒤 오른 비율이 높았습니다(검증 탭에서 확인).
  • 과열: 주봉 RSI 70 이상 등 → 신규 매수 중단. (과거 검증에서 익절·감량은 오히려 성과를 깎아, 앱은 “매수만 멈추고 보유 유지”를 기본으로 안내합니다.)
  • 3배 레버리지는 2차까지, 구조적 약세 의심·고평가는 1차까지로 자동 제한됩니다.

5. 검증 탭 — 믿을 만한지 확인하는 곳

  • 기준선과 비교: “아무 날이나 샀을 때” 오른 비율과 비교합니다. 신호가 기준선보다 높아야 의미가 있습니다.
  • 표본 외: 기준을 맞출 때 쓰지 않은 뒤쪽 기간으로 다시 확인한 숫자입니다(과최적화 방지).
  • 중립 ETF: 지수·섹터 ETF처럼 “잘 오른 종목만 고른” 편향이 적은 집합으로 보정 없이 검증한 숫자입니다.
  • 자동 보정: 데이터가 갱신되면 하루 한 번 스스로 다시 검증하고, 학습에 쓰지 않은 구간에서 기본값보다 나을 때만 새 기준을 채택합니다.
  • 실전 추적: 앱이 낸 신호를 기록해 두었다가 20·60일 뒤 실제 수익률로 채점합니다.
검증은 과거 결과이며 미래를 보장하지 않습니다. 현재 결과의 요지: 신호는 1~3개월 단기에 약간 유리하고, 오래 보유하면 단순 보유와 차이가 거의 없습니다.

6. 거물 거래 탭

  • 피드: 내부자(Form 4)·13F·의원 공시를 최신순으로. 카드를 누르면 신호 점수와 근거, SEC 원문 링크.
  • 인물: 최근 90일 인물별 매수·매도 금액. 13F 펀드: 분기 보유와 직전 분기 대비 변화. 의원: 하원 공식 색인.
  • 종목 상세 화면에도 그 종목의 거물 거래와 SEC 최근 공시(10-K/10-Q/8-K)가 함께 표시됩니다.
공시 자체가 늦습니다: Form 4는 거래 후 2영업일, 13F는 분기말+45일, 의원은 최대 45일. 이 정보는 참고용이며 매수 점수에는 넣지 않았습니다(과거 이력이 짧아 검증할 수 없기 때문).

7. 새로고침·지연

  • 자동: 앱을 켜 두거나 다시 열 때마다 확인(장중 2분·장외 10분). 화면을 아래로 당기면 즉시 새로고침.
  • 서버 갱신: GitHub가 미국 장중 5분마다 시세를 받아 배포합니다(GitHub 사정으로 몇 분 늦을 수 있음). 거물 거래는 30분마다.
  • 더 빠르게(선택, 무료): worker/proxy.js 를 Cloudflare Workers(무료)에 붙여넣어 배포하고, 앱 설정 → 프록시 주소에 주소를 넣으면 장중 20초마다 최신가로 갱신합니다. 개인정보는 전송되지 않고 종목 코드만 오갑니다.
  • 상단 칩: 초록 정상 · 노랑 지연 · 빨강 오래됨. 연결이 끊겨도 마지막 정상 데이터로 화면은 유지됩니다.

신호는 일봉 종가 기준이라 몇 분 지연은 결과에 거의 영향이 없습니다. 장중 값은 “잠정”입니다.

8. 개인정보·보안

  • 보유·현금·매매 기록은 휴대폰 안(브라우저 저장소)에만 있고 서버·저장소로 전송되지 않습니다.
  • 사이트에는 공개 시세·공개 공시·코드만 있습니다. SEC 연락처·FMP 키는 GitHub Secrets에만 저장됩니다.
  • 배포 때마다 tools/privacy_check.py 가 이메일·키·내 PC 경로가 파일에 섞였는지 검사하고, 발견되면 배포를 중단합니다.
  • API 키를 채팅·스크린샷에 올렸다면 해당 서비스에서 재발급하세요.
  • 설정 → 백업 내보내기로 내 데이터를 파일로 저장할 수 있습니다(기기 교체 시 불러오기).

9. 문제 해결

증상조치
상단이 빨강/노랑↻ 를 눌러보세요. 계속이면 GitHub Actions 탭에서 최근 실행이 성공했는지 확인.
거물 거래에 “SEC 접근 제한”SEC가 요청을 제한한 상태입니다(우회하지 않고 마지막 정상 데이터를 유지). 시간이 지나면 자동 재시도합니다. 계속되면 SEC_USER_AGENT 비밀 값(연락처 형식)을 확인.
화면이 예전 그대로설정 → 시세 캐시 삭제. 홈 화면 앱은 완전히 종료 후 다시 열기.
추천이 너무 적음/많음설정 → 내 매매 기준에서 현금 비중·차수 비율·한도를 조정.
검증이 안 돌아감검증 탭 → 지금 다시 검증. 시세 데이터가 3종목 이상 있어야 합니다.

10. 한계 (꼭 읽어주세요)

  • 과거 검증은 미래 수익을 보장하지 않습니다. 내 종목군은 많이 오른 종목 위주라 실제보다 좋아 보일 수 있습니다.
  • 영상 속 DB증권 HTS 신호·텔레그램 유료 신호는 데이터를 구할 수 없어 반영하지 못했습니다(대체: 가격·VIX·시장 폭으로 만든 자체 신호).
  • 시세는 야후 비공식 데이터, 거물 거래는 공식 공시(지연 있음). 투자 권유·자문이 아니며 모든 판단과 책임은 본인에게 있습니다.
